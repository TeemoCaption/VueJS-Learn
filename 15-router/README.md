# Vue 路由學習筆記

本單元練習的是：讓單頁應用程式依照網址，切換對應的頁面元件，而不必重新載入整個網頁。

## 路由在做什麼？

| 名稱 | 核心概念 | 本單元情境 |
|---|---|---|
| 服務端路由 | 每次換網址都向伺服器請求新頁面 | 傳統多頁網站常見 |
| 客戶端路由 | 先載入應用程式，再依網址替換畫面內容 | Vue 單頁應用程式的主要模式 |
| 路由 | 建立「網址 → 頁面元件」的對應 | `/about` 顯示關於我們頁面 |
| 路由器 | 管理網址、歷程紀錄與頁面切換 | Vue 的官方路由套件 |

切換流程可以記成：

`點擊路由連結 → 網址改變 → 路由器比對設定 → 路由顯示區替換頁面`

## 基本組成與資料流

| 元素 | 負責的事 | 使用判斷 |
|---|---|---|
| `createRouter()` | 建立路由器 | 每個應用程式建立一個路由器設定 |
| `routes` | 定義網址、名稱與頁面元件的對照 | 集中管理網站可前往的頁面 |
| `app.use(router)` | 將路由器註冊到 Vue 應用程式 | 必須在 `mount()` 前呼叫 |
| `<RouterLink>` | 建立不重新載入頁面的導覽連結 | 取代一般站內 `<a>` 連結 |
| `<RouterView>` | 顯示目前網址對應的頁面 | 放在頁面要被替換的位置 |
| `useRoute()` | 讀取目前路由資訊 | 需要讀取參數、查詢字串時 |
| `useRouter()` | 主動操作導覽 | 登入成功、送出表單後自動跳頁時 |

### 簡短範例：網址與頁面的對照

```js
{
  path: '/about',
  name: 'about',
  component: AboutView
}
```

當網址變成 `/about`，路由顯示區就會呈現 `AboutView`。`name` 是穩定的識別名稱，之後導覽時可避免直接依賴網址字串。

## 路由設定的重點

| 設定 | 作用 | 範例或注意事項 |
|---|---|---|
| `path` | 網址比對規則 | `/users/:id` 的 `:id` 是動態參數 |
| `name` | 為路由命名 | 導覽時建議優先使用名稱 |
| `component` | 比對成功後顯示的元件 | 頁面元件本質仍是一般 Vue 元件 |
| `children` | 建立巢狀頁面 | 父頁面必須再放一個 `<RouterView>` |
| `props: true` | 將 `params` 直接轉為元件屬性 | 適合 `/users/:id` 這類參數 |
| `props: { ... }` | 傳入固定屬性 | 適合頁面標題、版本等固定資料 |
| `props: route => ({ ... })` | 依目前路由計算屬性 | 適合把 `query.q` 轉成搜尋關鍵字 |
| `alias` | 同一條路由的另一個入口 | `/home` 可顯示首頁，網址仍保留 `/home` |
| `redirect` | 導向另一條路由 | 適合舊網址搬遷；導向後網址會改變 |

### 動態參數、查詢字串與屬性傳遞

| 網址 | 取得方式 | 適合的資料 |
|---|---|---|
| `/users/10` | `params.id`，可用 `props: true` 傳入 | 會員編號、商品編號等識別值 |
| `/search?q=vue` | `query.q`，可用函式模式轉為屬性 | 搜尋關鍵字、篩選條件、頁碼 |
| `/about` | 物件模式傳入固定值 | 不會隨網址變化的頁面設定 |

把路由資料轉成元件屬性後，頁面只需要宣告 `defineProps()`，不必直接依賴路由器；元件會較容易閱讀與重複使用。

## 巢狀路由：父頁面保留，子頁面替換

| 路徑層級 | 顯示內容 | 設計重點 |
|---|---|---|
| `/users/10` | 會員父頁面與預設子頁面 | 子路由的 `path: ''` 代表預設頁 |
| `/users/10/profile` | 會員父頁面與個人資料 | 父頁面的導覽與標題會保留 |
| `/users/10/posts` | 會員父頁面與文章 | 只有父頁面內的路由顯示區更新 |

### 簡短範例：子頁面的顯示位置

```vue
<main>
  <nav><!-- 會員子頁面導覽 --></nav>
  <RouterView />
</main>
```

外層的路由顯示區先放入會員頁面；網址再匹配到子路由時，這個內層路由顯示區才會放入個人資料或文章頁面。巢狀結構適合「共用版面不變、內容區切換」的畫面。

## 導覽方式與歷程紀錄

| 方法 | 適用時機 | 歷程紀錄行為 |
|---|---|---|
| `<RouterLink :to="{ name: 'about' }">` | 使用者主動點選選單 | 新增一筆紀錄 |
| `router.push(...)` | 程式依條件前往下一頁 | 新增一筆紀錄 |
| `router.replace(...)` | 登入後取代登入頁、避免返回上一頁 | 取代目前紀錄 |
| `router.go(-1)` | 實作「返回上一頁」 | 依瀏覽器既有紀錄移動 |

### 簡短範例：登入後不回到登入頁

```js
router.replace({
  name: 'user-profile',
  params: { id: userId }
})
```

這會前往該會員的個人資料頁，但以新的頁面取代登入頁。使用者按瀏覽器上一頁時，不會又回到已完成的登入畫面。

## 路由連結的啟用樣式

| 類別 | 何時套用 | 用途 |
|---|---|---|
| `linkActiveClass` | 目前網址符合該連結或其子路徑 | 標示目前所在區域 |
| `linkExactActiveClass` | 目前網址完全符合連結目標 | 精確標示目前頁面 |
| `active-class`、`exact-active-class` | 個別連結需要不同樣式時 | 覆寫全域設定 |

例如會員頁面的「個人資料」與「文章」可各自設定啟用樣式，讓使用者清楚知道目前正瀏覽哪一個子頁面。

## 網址歷程模式的選擇

| 模式 | 網址外觀 | 部署時的重點 | 適用情境 |
|---|---|---|---|
| `createWebHistory()` | `/about` | 伺服器需把未知路徑回傳 `index.html` | 一般正式單頁網站，本站目前使用 |
| `createWebHashHistory()` | `/#/about` | 通常不需額外處理路由回退 | 無法調整伺服器設定時 |
| `createMemoryHistory()` | 不與瀏覽器網址互動 | 不適合一般瀏覽器導覽 | 伺服器端渲染、測試或特殊環境 |

本專案使用 `createWebHistory(import.meta.env.BASE_URL)`，讓開發與部署到子目錄時的基礎路徑能和 Vite 設定一致。若採用此模式，直接重新整理 `/users/10` 時，伺服器也必須回傳應用程式入口頁，否則可能出現 404。

## 本單元速查

| 想完成的事 | 優先使用 |
|---|---|
| 在畫面上放網站導覽 | `<RouterLink>` |
| 決定頁面顯示位置 | `<RouterView>` |
| 讀取目前 `id` 或搜尋字 | `useRoute()` 或轉為元件屬性 |
| 登入成功後跳轉 | `useRouter()` 搭配 `replace()` |
| 保留共用頁面框架、切換內容 | `children` 與內層 `<RouterView>` |
| 讓舊網址改往新網址 | `redirect` |
| 為同一頁提供另一個不變更網址的入口 | `alias` |
