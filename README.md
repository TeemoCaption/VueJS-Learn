# Vue 衍生資料與狀態變化反應

這次要學的是：當 Vue 裡的資料改變時，什麼情況應該「重新得到一個值」，什麼情況應該「做一件事」。

先記住這個判斷：

| 需求 | 使用方式 |
| --- | --- |
| 從既有狀態推導出新值 | computed |
| 讓使用者編輯經過轉換的資料 | 可寫入的 computed（get / set） |
| 狀態改變後執行工作 | watch |

## 一、computed：描述「這個值應該是什麼」

當一個值可以由其他響應式資料計算出來，就使用 computed。總價、完整姓名、篩選清單與格式化文字，都屬於衍生資料。

衍生資料不應再額外保存一份，否則來源資料改變時，原始值與計算結果可能不同步。保留真正的來源狀態，讓 computed 根據來源自動產生結果。

computed 會記住它使用到的響應式依賴。依賴沒有改變時，多次讀取可以使用快取結果；依賴改變後，才會重新計算。

使用原則：

- 需要衍生資料，而且不需要參數時，優先使用 computed。
- 每次呼叫都要重新執行，或需要傳入參數時，使用方法。
- computed 只負責計算，不要在其中發送請求、修改其他狀態或操作外部系統。

## 二、可寫入的 computed：在兩種格式之間轉換

一般 computed 通常是唯讀的；如果畫面需要讀取格式化結果，也需要讓使用者修改它，就提供 get 與 set。

來源狀態 → get() → 畫面看到的值
來源狀態 ← set() ← 使用者輸入的值

get() 負責「如何讀取」：從來源狀態組合、格式化或轉換出畫面需要的值。它不應修改來源狀態。

set() 負責「如何寫回」：接收外部輸入，先整理與驗證，再更新真正的來源狀態。常見處理包括移除空白、拆解文字、移除格式符號、轉換數字與處理空值。

只有在「畫面格式」與「實際保存格式」不同，而且畫面仍需要編輯時，才需要 get / set。如果只是顯示計算結果，唯讀 computed 就足夠。

set() 應更新來源狀態，不要在 set() 裡再次寫入自己，否則容易造成遞迴更新或資料流混亂。它也很適合搭配 v-model，讓輸入框使用友善格式，同時把整理後的資料寫回來源。

## 三、watch：處理「資料改變後要做什麼」

watch 不負責產生新的顯示值，而是觀察指定的響應式資料，在資料改變後執行工作。

適合交給 watch 的工作包括：

- 根據搜尋條件呼叫服務。
- 將設定同步到瀏覽器或外部系統。
- 寫入操作紀錄。
- 顯示通知或觸發其他流程。
- 依照新值取消或重新建立非同步工作。

這些工作都屬於副作用，因為它們不只是回傳計算結果，而是會影響元件以外的環境。

監聽回呼通常可以取得新值與舊值，用來比較資料前後的差異。若需要在建立監聽器時先執行一次，才使用 immediate。

輸入框每打一個字都可能觸發 watch。如果監聽內容會發送請求，還要考慮防抖、節流、取消前一次請求與錯誤處理，避免產生過多或順序錯亂的請求。

## 四、computed 與 watch 怎麼選？

先問自己：

> 我需要的是一個新的值，還是一個資料改變後的動作？

| 判斷問題 | 選擇 |
| --- | --- |
| 結果可以由其他狀態直接算出來嗎？ | computed |
| 需要快取衍生結果嗎？ | computed |
| 使用者輸入需要轉換後再寫回來源嗎？ | computed 的 get / set |
| 資料改變後要呼叫服務、記錄或同步外部系統嗎？ | watch |

不要用 watch 製造衍生資料。如果完整姓名、總價或篩選結果只是由現有狀態計算出來，直接使用 computed 會更清楚。用 watch 同步另一個狀態，會增加狀態數量與同步時機，容易造成不同步。

記憶方式：

> 想知道「這個值應該是多少」使用 computed；想處理「這個值改變後要做什麼」使用 watch。

## 五、前一次計算結果不是歷史紀錄

某些 Vue 版本允許計算函式取得上一次回傳結果。它代表前一次的計算結果，不是完整的歷史紀錄，也不是所有狀態變化的清單。

它適合簡單的保留規則，例如新數值超過限制時，維持上一個可接受的顯示值。

如果需要復原、重做、完整變更歷史或查詢任意時間點，就應使用陣列或狀態管理保存歷史資料，不要只依賴前一次結果。

## 六、常見錯誤

- 把可以計算出的結果再存成一份狀態，造成資料不同步。
- 在 computed 裡發送請求或修改其他狀態。
- 在 get() 裡寫入資料，混淆讀取與更新責任。
- 在 set() 裡修改自己，造成遞迴或無法預期的更新。
- 把所有資料變化都交給 watch，卻沒有區分衍生資料與副作用。
- 監聽輸入內容時沒有處理過多請求、競速與錯誤。
- 把前一次計算結果誤當成完整歷史狀態。

## 最後的判斷口訣

> 想知道「值是多少」：用 computed。
> 想處理「改變後做什麼」：用 watch。
> 想讓使用者編輯格式化資料：用 computed 的 get / set。

只要先分清楚「計算」與「副作用」，就能避免把 watch、computed 與一般狀態混在一起使用。
